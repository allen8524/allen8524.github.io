프로젝트 개요

CineFlow는 Spring Boot와 Thymeleaf로 구현한 영화 예매 웹 애플리케이션입니다. 공개 사용자는 영화 목록·상세 조회에서 빠른예매, 좌석 선택, 결제, 예매 완료, 조회·취소까지 진행할 수 있고, 관리자는 영화·극장·상영관·상영일정·예매 상태를 운영할 수 있습니다. 백엔드에서는 상영일정, 좌석 상태, 예매 스냅샷, 결제 상태, 회원·비회원 조회 분기를 DB 기준으로 연결하는 데 초점을 맞췄습니다.

Spring Boot Thymeleaf JPA Security Flyway TMDB

개발 목적

영화 예매 서비스는 영화 → 극장 → 날짜 → 상영회차 → 좌석 → 결제 → 예매 완료 → 조회·취소로 이어지는 상태 변화가 많습니다. CineFlow는 이 흐름을 화면 단위로만 나누지 않고, 상영일정 ID와 좌석 상태, 예매번호, 결제 상태가 서버 로직과 DB 관계 안에서 이어지도록 구현하는 데 목적을 두었습니다.

공개 사용자는 영화 목록과 상세 화면에서 예매 가능한 작품을 확인하고 빠른예매로 이동할 수 있으며, 회원은 계정 기준으로 예매 내역을 조회하고 비회원은 예매번호와 연락처 기준으로 조회할 수 있습니다. 관리자는 영화, 극장, 상영관, 상영일정, 예매 현황을 별도 관리자 경로에서 운영하도록 분리했습니다.

백엔드 관점에서는 Spring Security로 공개·회원·관리자 접근 범위를 나누고, Flyway 마이그레이션으로 영화, 극장, 상영관, 상영일정, 좌석, 예매, 결제, 회원 테이블 변경 이력을 관리했습니다.

핵심 구현 포인트

1) 영화 정보 조회와 TMDB 메타데이터 연동

처리 방식: MovieController가 영화 목록과 상세 화면을 제공하고, PublicMovieMetadataService가 TMDB 인기·상영중·개봉예정 데이터와 로컬 영화 데이터를 합쳐 화면용 DTO를 만듭니다. TMDB 토큰이 없거나 API 호출이 실패하면 로컬 seed/fallback 데이터를 사용해 포스터, backdrop, overview, 상영 상태가 비어 보이지 않도록 했습니다.

2) 빠른예매 단계 처리

처리 방식: /booking에서 movieId, theaterId, date, scheduleId를 기준으로 선택값을 해석합니다. ScheduleService가 영화·극장·날짜 조합에 맞는 상영회차와 가능한 날짜를 조회하고, 선택된 회차는 좌석 선택 화면으로 전달됩니다.

3) 좌석 선택과 예매 데이터 연결

처리 방식: SeatService가 상영일정별 좌석 배치와 이미 예약된 좌석을 조회하고, BookingRequestDto가 성인·청소년·우대 인원과 선택 좌석을 함께 전달합니다. 예매 완료 시에는 ScheduleSeatRepository.findForUpdateByScheduleIdAndSeatCodes로 선택 좌석을 조회해 트랜잭션 안에서 예약 상태를 변경합니다.

4) 결제 및 예매 완료 처리

처리 방식: 실제 PG 연동이 아니라 포트폴리오 시연용 결제 흐름으로 구현했습니다. PaymentService는 결제수단, 금액, 결제상태, 거래번호를 저장하고, BookingService.completeBooking은 예매번호 생성, 예매 스냅샷 저장, 좌석 예약, 결제 기록 생성을 하나의 서비스 흐름으로 처리합니다.

5) 회원·비회원 예매 조회와 취소

처리 방식: 로그인 사용자는 user_id 기준으로 현재·지난·취소 예매를 조회하고, 비회원은 예매번호와 연락처 검증으로 단건 예매를 확인합니다. 취소 시 BookingStatus.CANCELED와 결제 취소 상태를 반영하고, 연결된 상영일정 좌석을 다시 사용 가능 상태로 복구합니다.

6) 관리자 운영 기능

처리 방식: AdminController는 대시보드, 예매 현황, 상영일정 상세와 관리자 취소를 담당하고, AdminManagementController는 영화·극장·상영관·상영일정 생성, 수정, 비활성화를 처리합니다. 이미 예매가 연결된 상영일정이나 상영관은 수정 범위를 제한해 운영 데이터가 깨지지 않도록 했습니다.

7) Spring Security 권한 분리

처리 방식: SecurityConfig에서 영화 조회, 빠른예매, 비회원 조회, 정적 리소스는 공개하고, /mypage/**와 /api/bookings/**는 인증 사용자, /admin/**은 ADMIN 권한으로 분리했습니다. 접근 권한이 없을 때는 /access-denied 화면으로 이동합니다.

8) Flyway 기반 DB 마이그레이션

처리 방식: V1__init_schema.sql부터 V6__movie_tmdb_columns.sql까지 스키마 변경을 파일 단위로 분리했습니다. dev 프로필은 H2와 seed 데이터로 시연을 빠르게 열고, local 프로필은 MySQL과 Flyway validate 기준으로 스키마를 확인하도록 구성했습니다.

메인 화면 데이터 구성

HomeController 모델 구성

HomeController.java는 메인 화면 요청에서 heroMovies, featuredMovie, boxOfficeMovies, nowShowingMovies, comingSoonMovies를 모델에 담습니다. 히어로, 랭킹/박스오피스형 목록, 현재 상영작, 개봉 예정작이 정적 HTML이 아니라 서버 모델 기준으로 렌더링됩니다.

TMDB 목록과 로컬 fallback 결합

PublicMovieMetadataService.java는 TMDB popular, now playing, upcoming 응답과 로컬 활성 영화, seed/fallback 데이터를 조합합니다. TMDB 토큰이 없거나 API 호출이 실패하면 로컬 데이터로 메인 화면 모델을 구성해 dev 시연 화면이 비어 보이지 않도록 했습니다.

템플릿 연결

templates/index.html은 컨트롤러에서 전달한 영화 목록을 화면 섹션별로 사용합니다. 포스터, backdrop, overview, runtime, genre 같은 표시용 메타데이터는 TMDB 상세 조회 결과가 있으면 보강하고, 없으면 로컬 영화 정보로 대체합니다.

제공 API

화면은 Thymeleaf 중심으로 구성했지만, 영화 조회와 로그인 사용자 예매 조회, 관리자 TMDB 검색은 JSON API로도 분리했습니다.

Method URL 인증 정책 역할
GET /api/movies 로그인 불필요 영화 목록 조회
GET /api/movies/{id} 로그인 불필요 영화 단건 조회
GET /api/bookings/current 로그인 필요 로그인 사용자의 현재 예매 조회
GET /api/bookings/past 로그인 필요 로그인 사용자의 지난 예매 조회
GET /admin/movies/tmdb/search ADMIN 권한 필요 관리자 영화 등록용 TMDB 검색
GET /admin/movies/tmdb/{tmdbId} ADMIN 권한 필요 관리자 영화 등록용 TMDB 상세 조회

공개 영화 API는 로그인 없이 접근할 수 있고, 예매 API는 로그인 사용자의 계정 기준으로 현재/지난 예매만 반환합니다. 관리자 TMDB API는 /admin/** 경로 정책에 따라 ADMIN 권한이 필요합니다.

구현 근거

주요 Controller

  • HomeController.java: 메인 화면의 히어로, 랭킹/박스오피스형 목록, 현재 상영작, 개봉 예정작 모델을 구성합니다.
  • MovieController.java: 영화 목록과 상세 페이지를 제공하고, 상영일정·극장 정보와 예매 이동 링크를 모델에 담습니다.
  • BookingController.java: 빠른예매, 좌석 선택, 결제 확인, 예매 완료, 예매 내역, 예매 취소 요청을 화면 흐름에 맞게 연결합니다.
  • AuthController.java: 로그인, 회원가입, 접근 거부 화면을 담당합니다.
  • AdminController.java: 관리자 대시보드, 예매 현황 필터, 상영일정 상세, 관리자 예매 취소를 처리합니다.
  • AdminManagementController.java: 영화, 극장, 상영관, 상영일정 생성·수정·비활성화 화면과 저장 요청을 담당합니다.
  • AdminMovieTmdbController.java: 관리자 영화 등록 화면에서 TMDB 검색과 상세 조회 API를 제공합니다.
  • MovieApiController.java / BookingApiController.java: 영화 조회 API와 인증 사용자 예매 조회 API를 제공합니다.

주요 Service

  • PublicMovieMetadataService.java: TMDB 공개 목록·상세 데이터와 로컬 영화 데이터를 병합하고, 토큰 미설정 또는 API 실패 시 fallback DTO를 반환합니다.
  • TmdbClient.java: TMDB 검색, 인기 영화, 현재 상영작, 개봉 예정작, 상세 메타데이터 API 호출을 담당합니다.
  • MovieService.java: 로컬 영화 CRUD, 예매 가능 영화 조회, 포스터·backdrop·overview fallback 값을 결정합니다.
  • ScheduleService.java: 영화·극장·날짜 기준 상영회차 조회, 관리자 상영일정 등록·수정·비활성화, 시간 중복 검증을 담당합니다.
  • TheaterService.java: 전체 극장과 영화별 활성 극장 조회를 담당합니다.
  • BookingService.java: 예매 요약 생성, 예매 완료, 예매 취소, 회원·비회원 접근 검증, 관리자 예매 필터를 담당합니다.
  • SeatService.java: 좌석 배치 조회, 좌석 코드 정규화, 인원·좌석 수 검증, 좌석별 금액 계산, 예약 좌석 잠금과 해제를 처리합니다.
  • PaymentService.java: 시연용 결제 성공 상태와 취소 상태, 거래번호와 취소 거래번호를 저장합니다.
  • AdminMovieTmdbService.java: 관리자 영화 등록에 필요한 TMDB 검색 결과와 상세 메타데이터를 변환합니다.
  • UserService.java: 회원가입, 로그인 사용자 조회, 관리자 계정 seed 생성을 지원합니다.

주요 Entity

  • Movie.java: 영화 기본 정보, TMDB ID, poster/backdrop path, overview, 예매 가능 여부, 노출 상태를 저장합니다.
  • Theater.java: 극장명, 지역, 위치, 설명, 활성 상태를 관리합니다.
  • Screen.java: 극장 내 상영관, 상영 타입, 좌석 수, 활성 상태를 관리합니다.
  • SeatTemplate.java: 상영관 기준 좌석 코드, 행/번호, 좌석 타입을 저장합니다.
  • Schedule.java: 영화, 상영관, 시작·종료 시간, 가격, 잔여 좌석을 연결합니다.
  • ScheduleSeat.java: 상영일정별 좌석 예약 상태와 임시 선점 필드를 저장합니다.
  • Booking.java: 예매번호, 고객 정보, 영화·극장·좌석 스냅샷, 예매 상태를 저장합니다.
  • BookingSeat.java: 예매 시점의 좌석 코드, 좌석 타입, 좌석별 금액을 저장합니다.
  • Payment.java: 예매와 1:1로 연결되는 결제수단, 금액, 결제 상태, 거래번호를 저장합니다.
  • User.java: 로그인 ID, 이메일, 암호화 비밀번호, USER/ADMIN 권한, 회원 예매 관계를 저장합니다.

주요 Template

  • templates/index.html: 메인 히어로, 랭킹/박스오피스형 목록, 현재 상영작, 개봉 예정작을 렌더링합니다.
  • templates/movies/list.html: 영화 목록과 예매 가능 작품의 빠른예매 이동을 제공합니다.
  • templates/movies/detail.html: 영화 상세, 극장별 상영일정, 선택 회차 예매 이동을 표시합니다.
  • templates/booking/quick.html: 영화, 극장, 날짜, 상영시간 선택 단계를 제공합니다.
  • templates/booking/seat.html: 상영일정별 좌석 배치, 인원 선택, 선택 좌석 전달 폼을 제공합니다.
  • templates/booking/payment.html: 예매 요약, 고객 정보, 결제수단 선택, 예매 완료 제출을 구성합니다.
  • templates/booking/complete.html: 예매 완료 또는 취소 완료 상태, 예매번호, 결제 정보, 취소 버튼을 표시합니다.
  • templates/booking/history.html: 회원·비회원 예매 조회, 현재·지난·취소 예매 목록을 보여줍니다.
  • templates/admin/index.html: 관리자 대시보드와 주요 운영 지표를 표시합니다.
  • templates/admin/bookings.html: 관리자 예매 목록, 필터, 취소 요청 화면을 구성합니다.
  • templates/admin/schedules.html: 관리자 상영일정 목록과 검색/관리 화면을 구성합니다.
  • templates/admin/schedule-detail.html: 상영 회차별 좌석 현황과 연결 예매를 표시합니다.
  • templates/admin/movies.html: 영화 목록, 생성·수정·비활성화 진입점을 제공합니다.
  • templates/admin/theaters.html: 극장 목록과 활성 상태 관리 화면을 제공합니다.
  • templates/admin/screens.html: 상영관 목록과 좌석 템플릿 기반 운영 화면을 제공합니다.
  • templates/auth/login.html / templates/auth/signup.html: 로그인과 회원가입 화면을 구성합니다.

DB Migration

  • V1__init_schema.sql: movies, theaters, screens, schedules, seat_templates, schedule_seats, bookings, booking_seats, payments 기본 테이블과 FK를 정의합니다.
  • V2__indexes_and_constraints.sql: 예매번호, 결제, 좌석 중복 방지 제약과 조회용 인덱스를 추가합니다.
  • V3__auth_schema.sql: users 테이블과 로그인 ID, 이메일, 권한 인덱스를 추가합니다.

주요 사용자 흐름

1) 영화 탐색

/movies에서 TMDB 목록과 로컬 활성 영화 데이터를 합친 영화 목록을 보여줍니다. 예매 가능한 로컬 영화는 빠른예매로 이동할 수 있는 ID를 함께 가집니다.

2) 영화 상세

/movies/{id}는 영화 메타데이터, 관련 영화, 극장별 상영일정, 가장 가까운 상영회차를 모델에 담습니다. 사용자는 상세 화면에서 영화 단위 또는 극장·회차 단위로 예매를 시작할 수 있습니다.

3) 빠른예매

/booking은 선택된 영화, 극장, 날짜를 기준으로 가능한 상영회차를 좁혀 줍니다. 선택값은 쿼리 파라미터로 유지되어 다음 선택 단계와 좌석 선택 링크에 이어집니다.

4) 좌석 선택

/booking/seat?scheduleId=...는 상영일정 ID를 기준으로 좌석 배치와 이미 예약된 좌석을 조회합니다. 사용자가 선택한 좌석 수와 인원 수가 일치하는지 검증한 뒤 결제 확인 단계로 이동합니다.

5) 결제 확인

/booking/payment는 선택 회차, 좌석, 인원, 고객 정보, 결제수단을 예매 요약으로 보여줍니다. 이 단계에서는 실제 PG 호출 대신 결제수단과 금액을 서비스 내부 결제 기록으로 저장할 준비를 합니다.

6) 예매 완료

/booking/complete 제출 시 BookingService가 좌석 잠금, 예매번호 생성, 예매 좌석 저장, 결제 기록 저장, 잔여 좌석 갱신을 처리합니다. 완료 화면은 예매번호와 모바일 티켓 형태의 확인 정보를 제공합니다.

7) 예매내역 조회

회원은 /mypage/bookings 또는 로그인 상태의 history 화면에서 계정 기준으로 예매를 확인합니다. 비회원은 /booking/history에서 예매번호와 연락처를 입력해 단건 예매를 조회합니다.

8) 예매 취소

상영 시작 전이고 예매 상태가 BOOKED인 경우 취소할 수 있습니다. 취소 요청은 예매 상태와 결제 상태를 바꾸고, 해당 예매 좌석을 상영일정 좌석 상태로 되돌립니다.

관리자 흐름

1) 관리자 로그인

관리자 계정은 Spring Security의 ADMIN 권한으로 /admin 이하 경로에 접근합니다. dev seed 환경에서는 ADMIN_USERNAME, ADMIN_PASSWORD 등 환경변수로 초기 계정을 만들 수 있습니다.

2) 영화 관리

/admin/movies에서 영화 목록을 확인하고, 생성·수정·비활성화를 처리합니다. TMDB 토큰이 있으면 관리자 영화 등록 폼에서 검색 결과를 가져와 poster path, backdrop path, overview, runtime metadata를 채울 수 있습니다.

3) 극장 관리

/admin/theaters에서 극장명, 지역, 위치, 설명, 활성 상태를 관리합니다. 공개 예매 화면에서는 활성 극장만 상영일정 조회와 예매 선택지로 노출됩니다.

4) 상영관 관리

/admin/screens에서 극장별 상영관, 상영 타입, 총 좌석 수를 관리합니다. 새 상영관 저장 시 좌석 템플릿을 생성하고, 이미 회차가 연결된 상영관은 극장 또는 좌석 수 변경을 제한합니다.

5) 상영일정 관리

/admin/schedules에서 영화, 극장, 상영관, 상영 시작·종료 시각, 가격을 등록합니다. 같은 상영관에서 시간이 겹치는 회차를 막고, 회차 생성 시 상영일정별 좌석 상태를 함께 생성합니다.

6) 예매 현황 관리

/admin/bookings는 예매 상태, 영화, 극장, 날짜 기준으로 예매를 필터링합니다. 관리자는 취소 가능한 예매를 관리자 사유로 취소할 수 있고, 상영일정 상세에서는 좌석 점유와 연결 예매를 함께 확인합니다.

DB 설계 요약

Flyway 마이그레이션은 영화, 극장, 상영관, 회차별 좌석 상태, 예매 스냅샷, 결제, 사용자 계정을 분리해 관리합니다.

테이블 역할

DB/상태 관리 관점

상영일정과 좌석 데이터 관계

상영관의 기본 좌석은 SeatTemplate에 저장하고, 실제 예매 가능 여부는 상영일정별 ScheduleSeat로 분리했습니다. 같은 좌석이라도 회차가 다르면 별도의 예약 상태를 가지므로, 상영일정 ID를 기준으로 좌석 선택과 예매 생성을 이어지게 구성했습니다.

예매 스냅샷 저장

Booking은 Schedule과 연결되면서도 영화 제목, 포스터, 극장명, 상영관명, 좌석명, 금액을 예매 당시 값으로 저장합니다. 운영 데이터가 나중에 수정되더라도 예매 내역 화면에서 당시 예매 정보를 확인할 수 있게 하기 위한 구조입니다.

예매 상태와 결제 상태 분리

예매는 BookingStatus, 결제는 PaymentStatus로 나눠 저장합니다. 취소 시 예매는 CANCELED로, 결제는 CANCELED로 변경하고 취소 시각과 취소 거래번호를 남깁니다.

취소 처리와 좌석 복구

취소 가능 여부는 예매 상태와 상영 시작 시간을 기준으로 판단합니다. 취소가 승인되면 예매에 연결된 좌석 코드를 다시 찾아 ScheduleSeat.reserved를 false로 바꾸고, 상영일정의 잔여 좌석 수를 다시 계산합니다.

회원·비회원 조회 기준

회원 예매는 bookings.user_id와 현재 인증 사용자를 기준으로 접근을 제한합니다. 비회원 예매는 계정이 없으므로 예매번호와 연락처를 기준으로 조회하고, 회원 예매는 다른 사용자가 예매번호만으로 접근하지 못하도록 검증합니다.

마이그레이션과 조회 성능

Flyway는 테이블 생성, 제약 조건, 인덱스, 회원 관계, 관리자 활성 상태, TMDB 컬럼을 단계별로 관리합니다. 예매번호 unique, 상영일정·좌석 unique, status와 schedule_id 인덱스처럼 예매 조회와 좌석 중복 방지에 필요한 제약을 명시했습니다.

보안 설계

SecurityConfig.java에서 공개 화면, 로그인 사용자 화면, 관리자 화면을 경로 기준으로 분리했습니다. 비밀번호는 BCryptPasswordEncoder로 해시 저장합니다.

구분 접근 정책
공개 페이지 메인, 영화 목록/상세, 빠른예매 진입, 비회원 예매 조회, 고객지원, 정적 리소스, /api/movies/**
로그인 필요 /mypage/**, /api/bookings/**
관리자 필요 /admin/**는 ADMIN role 필요
로그인/로그아웃 로그인 페이지와 처리 URL은 /login, 로그아웃 URL은 /logout
접근 거부 권한 부족 시 /access-denied 화면으로 이동
개발 편의 H2 console은 dev 확인을 위해 frame same-origin 설정과 /h2-console/** 경로를 사용합니다.

TMDB 연동/fallback/cache 전략

API 호출 조건

TmdbProperties의 TMDB_BEARER_TOKEN이 설정되어 있으면 TmdbClient가 TMDB API를 호출합니다. 토큰이 없으면 외부 호출을 진행하지 않고 로컬 영화 데이터로 화면 DTO를 구성합니다.

상세 조회와 검색 매칭

로컬 영화에 TMDB ID가 있으면 상세 조회를 우선 사용하고, TMDB ID가 없으면 제목과 개봉연도 기반 검색으로 매칭합니다. 제목이 맞지 않는 검색 결과를 첫 번째 결과라는 이유만으로 강제 사용하지 않도록 PublicMovieMetadataServiceTest에서 검증합니다.

표시 메타데이터

TMDB 상세 응답이 있으면 poster, backdrop, overview, runtime, genre, 관람등급 성격의 메타데이터를 화면 표시용 DTO에 반영합니다. 로컬 영화에 이미 runtime이나 관람등급 값이 있으면 해당 값을 우선 유지합니다.

fallback과 TTL 캐시

TMDB API가 실패하거나 설정되지 않은 경우 로컬 seed/fallback 데이터를 사용합니다. live metadata는 5분 TTL, fallback metadata는 30초 TTL 캐시를 적용해 반복 호출을 줄이면서 실패 후 재시도 여지를 남겼습니다.

예외 및 안정성 처리

예매 진입 검증

  • 좌석 선택 화면에서 상영일정이 없으면 빠른예매 화면으로 되돌리고, 존재하지 않는 상영일정이면 오류 메시지와 함께 다시 선택하도록 처리합니다.
  • 상영일정 ID를 기준으로 좌석 상태와 예매 생성을 연결해 회차별 예약 상태를 분리합니다.

좌석과 결제 전 검증

  • 선택 좌석 수와 관람 인원 수가 다르면 예매 진행을 막습니다.
  • 이미 예약된 좌석이 포함되면 예매 요약 또는 예매 완료 단계에서 차단합니다.
  • 예매 완료 시 findForUpdateByScheduleIdAndSeatCodes로 좌석을 잠근 뒤 예약 상태, 예매 좌석 스냅샷, 결제 상태를 함께 저장합니다.

예매 조회와 취소 제한

  • 회원 예매는 user_id 기준으로 접근을 제한하고, 비회원 예매는 예매번호와 연락처 검증으로 조회합니다.
  • 이미 취소된 예매는 다시 취소할 수 없고, 상영 시작 이후 예매도 취소할 수 없습니다.
  • 취소가 승인되면 예약 좌석을 복구하고 예매 상태와 결제 상태를 CANCELED로 갱신합니다.

외부 입력 방어

  • 취소 후 이동 경로는 /로 시작하는 안전한 내부 경로만 허용하고, 외부 redirect나 줄바꿈이 포함된 값은 사용하지 않습니다.
  • TMDB 미설정이나 네트워크 오류는 로그를 남긴 뒤 로컬 fallback 데이터로 화면 모델을 유지합니다.

환경 구성

기본 실행 환경은 Java 17과 Gradle Wrapper입니다. build.gradle에는 Spring Boot Web, Thymeleaf, JPA, Security, Validation, Flyway, H2, MySQL Connector, Lombok, Spring Boot Test 의존성이 포함되어 있습니다.

dev 프로필은 H2 in-memory DB와 seed 데이터를 사용해 바로 시연할 수 있고, local 프로필은 MySQL 연결 정보와 Hibernate validate, Flyway 검증을 사용합니다. TMDB 연동은 TMDB_BEARER_TOKEN 환경변수로 켜며, 토큰이 없어도 로컬 seed/fallback 데이터로 화면이 유지되도록 구성했습니다.

현재 테스트는 PublicMovieMetadataServiceTest를 중심으로 TMDB 상세 조회, 제목 기반 검색 매칭, 로컬 fallback, 인기 영화 연결, TTL 캐시 갱신 흐름을 검증합니다. GitHub Actions에서는 Java 17과 Gradle Wrapper로 테스트를 실행하도록 구성했습니다.

한계 및 개선 가능성

실제 결제 연동

현재 결제는 PaymentService에서 결제 성공과 취소 상태를 저장하는 시연용 흐름입니다. 운영 서비스로 확장한다면 PG 승인, 실패, 환불 콜백, 영수증 검증을 별도 어댑터와 상태 전이로 분리할 수 있습니다.

좌석 임시 선점 정책

예매 완료 시점에는 좌석 잠금과 예약 처리를 트랜잭션 안에서 수행하지만, 사용자가 좌석 선택 화면에 오래 머무르는 동안의 임시 선점 만료 정책은 더 정교하게 만들 수 있습니다. ScheduleSeat.held와 holdExpiresAt 필드를 활용해 선점 생성과 만료 배치를 분리하는 방향이 적합합니다.

운영 secret 관리

TMDB 토큰과 관리자 초기 계정은 환경변수로 받도록 구성했지만, 운영 배포에서는 secret manager, 관리자 초기 비밀번호 회전, seed 계정 비활성 정책을 더 엄격하게 적용해야 합니다.

검색·관리 화면 확장

영화 검색/필터 조건, 관리자 통계 차트, 사용자 프로필 수정 화면은 이후 보강할 수 있습니다. 현재 설명에서는 이 항목들을 구현 완료 기능이 아니라 확장 가능성으로만 구분했습니다.

알림과 정책 보강

예매 완료·취소 알림 메일 또는 SMS 발송, 취소 수수료 정책, API 문서화는 아직 구현 범위에 포함하지 않았습니다. 결제와 취소 상태가 분리되어 있으므로 이후 정책 레이어를 추가하기 좋은 지점으로 남아 있습니다.

로컬 실행 환경 보강

현재 local 프로필은 MySQL 접속 환경변수와 Flyway validate 기준으로 실행됩니다. Docker Compose 기반 MySQL 실행 환경을 추가하면 다른 환경에서도 같은 DB 구성을 더 쉽게 재현할 수 있습니다.

테스트 보강

현재 포트폴리오에서 강조한 테스트 범위는 TMDB 메타데이터 병합, 검색 매칭, fallback, TTL 캐시입니다. 예매 완료·취소·좌석 잠금에 대한 서비스 통합 테스트를 추가하면 핵심 예매 상태 전이를 더 안정적으로 검증할 수 있습니다.
