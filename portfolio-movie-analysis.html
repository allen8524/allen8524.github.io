프로젝트 개요

Cine21 영화 데이터를 저장 CSV 기준으로 전처리하고, PCA·상관분석·선형회귀를 통해 영화 평점과 관객 수 등 수치형 지표의 관계를 분석한 데이터 분석 프로젝트입니다. 사용자는 포스터와 시각화 이미지를 먼저 확인한 뒤, 전처리 기준, PCA 해석, 회귀 결과, 한계와 개선 방향 순서로 분석 흐름을 따라갈 수 있습니다. 구현 범위는 오프라인 CSV 로드부터 결측값·이상치 처리, 정규화, 분석 실행, 결과 이미지와 요약 파일 저장까지입니다.

Python pandas PCA 회귀분석

개발 목적

이 프로젝트의 목적은 Cine21에서 확보한 영화 데이터를 단순 목록이 아니라 분석 가능한 데이터셋으로 바꾸는 것이었습니다. 저장된 CSV를 기준으로 실행하도록 만들어 인터넷 연결 상태나 수집 페이지 변화에 영향을 덜 받게 했고, 같은 파일을 다시 실행했을 때 동일한 전처리와 분석 결과를 확인할 수 있는 흐름을 우선했습니다.

영화 데이터에는 제목, 장르, 국가처럼 문자열 중심의 정보와 상영 시간, 누적 관객 수, 전문가 평점, 네티즌 평점처럼 단위가 다른 수치형 정보가 함께 들어 있습니다. 문자열 결측값은 "정보없음"으로 대체하고, 수치형 결측값은 컬럼 성격에 따라 평균 또는 중앙값으로 보완해 분석 단계에서 누락된 값 때문에 흐름이 끊기지 않도록 처리했습니다.

관객 수처럼 분포가 크게 치우칠 수 있는 컬럼은 IQR 기준으로 이상치를 완화했습니다. 이후 runtime_min, audience_total, cine21_score_detail, netizen_score 등 단위가 서로 다른 변수를 MinMaxScaler로 정규화해 PCA 입력값의 범위를 맞췄습니다.

PCA는 여러 수치형 지표를 주성분으로 축약해 데이터 구조를 요약하기 위해 적용했습니다. PC1 설명분산비는 약 0.539531이며, PC1과 PC2를 함께 보면 약 81.58%를 설명할 수 있어 두 축만으로도 주요 수치형 변동을 어느 정도 확인할 수 있다는 해석을 남겼습니다.

마지막으로 Pearson, Spearman, Kendall 상관계수를 비교하고 PC1 기반 선형회귀를 수행했습니다. 회귀 결과는 R² 0.275227, MSE 0.057193으로 저장했으며, 단일 주성분만으로 평점을 완전히 설명하기는 어렵다는 한계까지 함께 기록했습니다.

핵심 구현 포인트

1) 저장 CSV 기준 오프라인 분석 흐름

처리 방식: data/hms202212004.csv를 기준 데이터로 로드하고, 수집 단계와 분석 실행 단계를 분리해 인터넷 연결 없이도 분석을 재현할 수 있게 했습니다.

구현 이유: 외부 페이지 구조가 바뀌거나 네트워크가 불안정해도 동일한 입력 데이터로 전처리, PCA, 회귀 결과를 다시 확인하기 위해서입니다.

확인 가능한 파일 또는 화면: data/hms202212004.csv, src/hms_project_202212004.py, notebooks/hms_project_202212004.ipynb

2) 결측값 처리 기준 분리

처리 방식: 문자열 컬럼은 "정보없음"처럼 의미를 남길 수 있는 값으로 대체하고, 수치형 컬럼은 평균 또는 중앙값으로 보완해 분석 입력값을 유지했습니다.

구현 이유: 문자열 결측은 값이 없다는 사실 자체가 정보가 될 수 있고, 수치형 결측은 PCA와 회귀분석에서 계산 오류를 만들 수 있어 컬럼 유형별 처리가 필요했습니다.

확인 가능한 파일 또는 화면: src/hms_project_202212004.py, outputs/analysis_summary.txt

3) IQR 기반 이상치 완화

처리 방식: audience_total처럼 일부 영화에 값이 크게 몰릴 수 있는 컬럼은 IQR 범위를 기준으로 극단값 영향을 줄였습니다.

구현 이유: 관객 수는 평점보다 단위와 분산이 커서 그대로 사용하면 정규화 전후의 분석 축에 과도한 영향을 줄 수 있기 때문입니다.

확인 가능한 파일 또는 화면: src/hms_project_202212004.py, docs/images/correlation_heatmap.png

4) MinMaxScaler 정규화

처리 방식: runtime_min, audience_total, cine21_score_detail, netizen_score 등 단위가 다른 수치형 변수를 0과 1 사이 범위로 정규화했습니다.

구현 이유: PCA는 입력 변수의 스케일 영향을 받기 때문에, 상영 시간과 관객 수처럼 단위가 다른 값이 같은 기준에서 비교되도록 맞춰야 했습니다.

확인 가능한 파일 또는 화면: src/hms_project_202212004.py, docs/images/pca_explained_variance.png

5) PCA 설명분산비 해석

처리 방식: 여러 수치형 지표를 주성분으로 축약하고, PC1 설명분산비 약 0.539531과 PC1+PC2 기준 약 81.58% 설명 가능성을 결과에 남겼습니다.

구현 이유: 변수 간 관계를 개별 컬럼으로만 보지 않고, 주요 변동 축으로 축약했을 때 데이터가 어느 정도 설명되는지 확인하기 위해서입니다.

확인 가능한 파일 또는 화면: docs/images/pca_explained_variance.png, outputs/analysis_summary.txt

6) 상관분석과 회귀분석 비교

처리 방식: Pearson, Spearman, Kendall 상관계수를 비교하고, PC1 기반 선형회귀로 예측 평점과 실제 평점의 차이를 그래프로 저장했습니다.

구현 이유: 전문가 평점과 관객 평점 사이에는 양의 상관이 있으나 강한 수준으로 단정하기 어렵고, PC1만으로 평점을 설명하는 데 한계가 있음을 수치와 시각화로 검증하기 위해서입니다.

확인 가능한 파일 또는 화면: docs/images/correlation_heatmap.png, docs/images/actual_vs_predicted.png, outputs/analysis_summary.txt

구현 흐름 상세

1) 데이터 로드

저장된 CSV를 입력으로 삼아 분석 시작점을 고정했습니다. 이 방식은 수집 환경과 분석 환경을 분리해 결과 재현 가능성을 높입니다.

2) 결측값 처리

문자열 컬럼과 수치형 컬럼을 나누어 대체 기준을 다르게 적용했습니다. 결측으로 인해 PCA와 회귀 단계가 중단되지 않도록 방어했습니다.

3) 이상치 완화

관객 수처럼 편차가 큰 값은 IQR 기준으로 완화해 특정 영화가 전체 분석 축을 과도하게 흔들지 않도록 했습니다.

4) 정규화

서로 다른 단위의 수치형 변수를 MinMaxScaler로 정규화해 PCA 입력값의 범위를 맞췄습니다.

5) PCA

정규화된 수치형 지표를 주성분으로 축약하고 설명분산비를 저장했습니다.

6) 상관분석

Pearson, Spearman, Kendall을 함께 비교해 선형 관계와 순위 기반 관계를 나누어 확인했습니다.

7) 회귀분석

PC1을 독립 변수로 사용한 선형회귀를 실행하고 R² 0.275227, MSE 0.057193을 요약 파일에 남겼습니다.

8) 결과 이미지 저장

PCA 설명분산비 그래프, 상관관계 히트맵, 실제/예측 평점 그래프를 저장해 README와 상세 페이지에서 다시 확인할 수 있게 했습니다.

개선 여지

월별 평점 데이터가 부족하면 ARIMA 분석은 건너뛰도록 방어 로직을 두었습니다. 이후 데이터가 충분해지면 시계열 분석을 별도 단계로 분리해 비교할 수 있습니다.

구현 중 확인한 한계와 개선 방향

1) 데이터 규모 확장

현재 데이터는 약 150행 규모이므로 특정 기간이나 특정 영화군의 특성이 결과에 반영될 수 있습니다. 표본을 확장하면 상관계수와 회귀 지표의 안정성을 다시 검증할 수 있습니다.

2) 외부 데이터 결합

영화 평점과 흥행은 장르, 배급, 마케팅, 개봉 시기 등 외부 요인의 영향을 받습니다. KOBIS 또는 TMDB 데이터를 결합하면 관객 수와 평점을 더 다양한 피처로 설명할 수 있습니다.

3) 피처 확장

장르, 국가, 개봉 시기, 배급 규모를 분석 피처로 추가하면 현재 수치형 변수 중심의 분석 한계를 줄일 수 있습니다.

4) 모델 비교

PC1 단일 회귀는 평점을 완전히 설명하기 어렵습니다. 다중 회귀, 규제 회귀, 비선형 모델을 비교하면 예측 성능과 해석 가능성의 차이를 확인할 수 있습니다.

5) 수집 단계와 분석 단계 분리 강화

현재도 저장 CSV를 기준으로 실행하지만, 향후 수집 스크립트와 분석 스크립트의 입출력 계약을 더 명확히 나누면 데이터 갱신과 분석 재실행을 더 안정적으로 관리할 수 있습니다.
