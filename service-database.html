DB 설계 및 연동

  1. 홈
  2. DB 설계 및 연동

기능 요구사항을 테이블 구조와 쿼리로 연결해 구현했습니다

쇼핑몰, e스포츠 포털, 베이커리 프로젝트에서 화면 기능이 요구하는 데이터를 관계형 데이터베이스 구조로 나눠 설계했습니다. 회원/상품/주문 관계, 팀/선수/경기 결과 흐름, 제품/재고/판매 데이터 연결을 프로젝트별로 구현한 내용을 정리했습니다.

핵심 구현 내용

단순 테이블 생성이 아니라 화면 흐름을 기준으로 데이터 관계를 나눈 경험을 중심으로 정리했습니다. 관리자 화면과 사용자 화면이 같은 데이터를 다른 목적에서 조회하는 구조를 프로젝트별로 맞췄습니다.

테이블 관계 설계와 정규화

쇼핑몰 프로젝트에서 회원, 상품, 주문, 주문상세를 분리해 주문 마스터/상세 구조를 구성했습니다. 주문 내역 조회와 관리자 주문 처리에 필요한 관계를 PK/FK로 연결해 중복 저장을 줄였습니다.

CRUD 및 조회 쿼리 흐름

e스포츠 포털에서는 팀, 선수, 경기 일정, 경기 결과, 순위 집계 데이터를 JOIN 기반으로 조회했습니다. 콘텐츠 목록과 경기 데이터에 검색·정렬·페이징 조건을 분리해 화면별 조회 쿼리를 정리했습니다.

웹 기능과 DB 연동

베이커리 프로젝트에서는 제품, 재고, 판매 데이터를 나눠 저장하고 관리자 화면에서 재고·판매 현황을 함께 조회하도록 연결했습니다. 같은 데이터를 사용자 조회 화면과 관리자 관리 화면에서 목적에 맞게 다르게 노출하도록 구성했습니다.

예외 처리와 데이터 일관성

주문 저장 시 주문상세 누락, 경기 결과 입력 시 순위 집계 불일치, 판매 등록 시 재고 음수 같은 예외를 확인해 검증 로직을 적용했습니다. 수정/삭제 시 연관 데이터 영향 범위를 함께 점검해 일관성을 유지했습니다.

DB 설계/연동 구현 포인트

01

요구사항 기반 모델링

화면 기능을 기준으로 엔터티와 관계를 정의하고 ERD를 먼저 작성했습니다.

02

정규화 및 키 설계

중복 데이터를 줄이고 PK/FK 기준을 명확히 정리했습니다.

03

쿼리/연동 구현

CRUD와 JOIN 조회를 구현하고 컨트롤러-서비스-DB 흐름을 연결했습니다.

04

무결성 검증

예외 입력과 연관 데이터 변경 시나리오를 점검해 일관성을 보완했습니다.

주 사용 기술

  • DBMS: MySQL, MariaDB
  • 모델링: ERD, 정규화, PK/FK 관계 설계
  • 쿼리: CRUD, JOIN, 집계 쿼리 구성
  • 검증: 데이터 무결성 및 예외 입력 점검

구현 포인트

  • 관계형 설계: 회원/상품/주문 관계와 주문 마스터/상세 분리
  • 경기 데이터: 팀/선수/경기 결과와 순위 집계 조회 구조 구성
  • 판매 데이터: 제품/재고/판매 데이터 연결 및 관리 화면 반영
  • 화면 연동: 관리자 화면·사용자 화면 목적에 맞는 조회 분리

관련 프로젝트 연결

  • 온라인 쇼핑몰: 회원/상품/주문 관계와 주문 마스터·상세 분리 구조를 실제 주문 기능에 적용한 프로젝트입니다.
  • e스포츠 포털: 팀·선수·경기·결과 데이터를 연결하고 순위 집계 조회까지 구성한 프로젝트입니다.
  • 베이커리 관리 웹: 제품/재고/판매 데이터를 연결해 관리자 운영 화면과 조회 화면을 분리한 프로젝트입니다.

사용 기술

  • 쇼핑몰 회원·상품·주문과 주문 상세 데이터 관계 설계
  • e스포츠 팀·선수·경기·결과·순위 데이터 흐름 분리
  • 베이커리 제품·재고·판매 데이터를 연결해 조회/저장 연동
