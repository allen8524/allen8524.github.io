주문 및 장바구니

  1. 홈
  2. 주문 및 장바구니

상품 선택부터 주문 완료까지 끊기지 않도록 주문 흐름을 정리했습니다

쇼핑몰 판매관리 프로젝트에서 장바구니, 주문서, 주문 저장, 관리자 주문 처리를 단계별로 나눠 적용했습니다. 사용자 화면에서 생성된 주문이 주문번호 기준으로 관리자 화면에서 확인·처리되도록 주문 마스터/상세 구조를 함께 사용했습니다.

핵심 구현 내용

쇼핑몰 프로젝트의 실제 주문 라이프사이클을 기준으로 정리했습니다. 장바구니 데이터가 주문서·주문 저장으로 이어지고, 저장된 주문이 관리자 주문 처리 화면에서 같은 주문번호로 조회되도록 맞췄습니다.

상품 선택 및 상세 조회

상품 목록/상세 화면에서 옵션·수량 선택값이 장바구니 또는 주문서에 바로 반영되게 처리했습니다. 품절 상품과 비정상 요청은 안내 메시지와 함께 차단했습니다.

장바구니 처리와 수량 변경

장바구니는 쿠키/JSON에 상품 ID·수량·금액을 저장하고, 수량 변경·선택 삭제 시 합계가 즉시 다시 계산되게 했습니다. 중복 담기는 수량을 병합하고 비정상 수량은 저장 전에 차단했습니다.

주문 처리 및 상태 관리

주문서 제출 시 주문번호를 생성하고 주문 마스터/상세 데이터를 분리해 저장했습니다. 주문 상태는 접수·처리·완료 단계로 관리했으며, 사용자 주문 내역과 관리자 주문 처리 화면에서 동일한 상태 값을 조회하도록 맞췄습니다.

예외 케이스 대응

로그인 세션 없이 주문서에 접근한 경우, 이미 품절된 상품 주문, 동일 요청 재전송을 각각 검증했습니다. 이 과정에서 주문 저장 전 재고·총액·주문 상태를 재확인해 중복 처리와 데이터 꼬임을 줄였습니다.

주문 기능 구현 포인트

01

주문 플로우 정의

상품 상세 → 장바구니 → 주문서 → 주문 완료 흐름을 먼저 고정했습니다.

02

상태 데이터 설계

장바구니 JSON 구조와 주문 마스터/주문 상세 테이블, 주문 상태 값을 함께 정의했습니다.

03

화면/DB 동기화

사용자 주문 저장 후 관리자 주문 처리 화면에서도 주문번호 기준으로 같은 주문 데이터가 조회되도록 맞췄습니다.

04

예외 상황 점검

로그인 만료, 비정상 수량, 중복 요청 상황을 테스트하며 처리 로직을 보완했습니다.

프로젝트 적용 근거

적용 프로젝트

쇼핑몰 판매관리 사이트에서 상품 선택부터 주문 저장까지 흐름을 나누어 처리하고, 같은 주문 데이터를 사용자 주문 조회와 관리자 주문 관리에서 함께 확인하게 했습니다.

관련 기능 화면

상품 상세, 장바구니, 주문서, 주문 완료, 주문 조회, 관리자 주문 관리 화면을 기준으로 동선을 맞췄습니다. 결제 연동보다 결제수단 선택값 저장과 주문 데이터 처리 흐름을 중심으로 정리했습니다.

관련 코드/DB 근거

관련 파일: cart.php, cart_edit.php, order.php, order_ok.php, order_list.php, admin/jumun.php, admin/jumun_info.php
저장 순서: 장바구니 선택 → 주문서 작성 → 주문번호 생성 → 주문 마스터 INSERT → 주문 상세 반복 INSERT → 사용자 주문 내역 조회 → 관리자 주문 관리 조회
상태 기준: 접수 · 처리 · 완료 단계 값을 사용자/관리자 화면에서 같은 주문번호 기준으로 조회
분리 이유: 장바구니는 임시 선택 데이터로 사용하고, 주문 완료 시 주문 단위 정보(마스터)와 상품 단위 정보(상세)를 분리 저장했습니다.

주 사용 기술

  • 주문 로직: PHP 기반 주문 생성·상태 변경 처리
  • 장바구니: 쿠키 기반 항목 저장과 JSON 데이터 처리
  • 데이터 구조: 주문 마스터/상세 테이블 분리 저장
  • 운영 확인: 관리자 주문 조회 화면 연동

구현 포인트

  • 장바구니: 쿠키/JSON 기반 항목 저장, 수량 변경, 총액 재계산 처리
  • 주문서: 주문번호 생성 후 주문 마스터/상세 분리 저장
  • 주문 상태: 접수·처리·완료 단계 값 관리와 변경 이력 확인
  • 관리자 연동: 사용자 주문 → 관리자 주문 처리 화면으로 데이터 연계

관련 프로젝트 연결

  • 쇼핑몰 판매관리 사이트: 장바구니부터 주문서, 주문 저장, 관리자 주문 처리까지 전체 주문 흐름의 핵심 근거입니다.
  • 베이커리 판매관리 웹사이트: 판매 데이터 집계 화면으로 주문/판매 상태를 운영 관점에서 확인하는 흐름을 보완했습니다.
  • 트러블슈팅 기록: 주문 흐름 예외 처리 과정 블로그 정리

사용 기술

  • 쇼핑몰 프로젝트에서 장바구니 → 주문서 데이터 전달 구조 구현
  • 주문 저장 시 주문번호 기준 마스터/상세 분리 처리
  • 저장된 주문을 관리자 주문 확인 화면에서 조회하도록 연결
