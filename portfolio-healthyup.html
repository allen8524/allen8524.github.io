기타 프로젝트 · iOS 2026

프로젝트 개요

UIKit과 Storyboard를 활용해 BMI 계산, 운동 정보 탐색, 운동 영상 재생, 운동 계획 설정을 탭 기반으로 연결한 iOS 건강관리 앱입니다. 사용자는 키와 체중을 입력해 결과를 확인한 뒤 운동 정보 WebView, 로컬 운동 영상, 운동 계획 화면으로 이동할 수 있습니다. 구현 범위는 입력값 검증, 성별 기준 BMI 분기, 결과 UI 피드백, WebKit/AVKit 화면, Storyboard 기반 탭 흐름과 리소스 정리입니다.

Swift UIKit Storyboard WebKit

개발 목적

HealthyUp은 BMI 계산 화면에서 끝나는 앱이 아니라, 계산 결과 이후 사용자가 운동 정보를 확인하고 영상과 계획 화면으로 이어갈 수 있는 흐름을 목표로 만들었습니다. 이를 위해 Tab Bar Controller를 기준으로 BMI, 운동정보, 운동영상, 운동계획 화면을 나누고 각 탭의 역할을 분리했습니다.

첫 화면에서는 키와 체중 입력값을 검증하는 것이 중요했습니다. 빈 값이나 숫자 변환 실패를 처리하지 않으면 BMI 계산식이 의미 없는 결과를 만들 수 있으므로, ViewController에서 입력 검증과 계산, 결과 문구 표시를 같은 흐름 안에서 확인할 수 있게 했습니다.

BMI 결과는 성별 선택에 따라 정상 범위 기준을 다르게 분기하도록 처리했습니다. 결과 문구, 색상, 이미지 테두리 피드백을 함께 바꿔 사용자가 계산 결과를 텍스트와 시각 요소로 동시에 확인하도록 했습니다.

운동 정보 화면은 WKWebView로 구현해 앱 내부에서 외부 운동 관련 정보 페이지를 탐색할 수 있게 했습니다. 운동 영상 화면은 AVKit과 AVPlayerViewController를 사용해 벤치프레스, 스쿼트, 데드리프트 같은 로컬 mp4 영상을 재생하도록 연결했습니다.

운동 계획 화면은 UISlider, UIStepper, UISegmentedControl을 사용해 운동 강도, 시간, 세트 수를 조정하고 입력값에 따라 요약 문구를 갱신합니다. 계산 결과에서 정보 탐색, 영상 확인, 계획 설정으로 이어지는 사용 순서를 탭 구조로 확인할 수 있습니다.

핵심 구현 포인트

1) BMI 입력값 검증과 계산

처리 방식: ViewController에서 키와 체중 입력값의 빈 값, 숫자 변환 실패를 검증한 뒤 BMI 계산 공식을 적용했습니다.

구현 이유: 계산 결과의 신뢰성은 입력값 검증에서 시작되므로, 잘못된 입력이 결과 UI로 넘어가지 않도록 방어했습니다.

확인 가능한 파일 또는 화면: ViewController.swift, BMI 결과 화면

2) 성별 기준 정상 BMI 범위 분기

처리 방식: 성별 선택값에 따라 정상 BMI 범위를 나누고, 결과별 문구와 색상, 이미지 테두리 피드백을 갱신했습니다.

구현 이유: 같은 BMI 값이라도 화면에서 어떤 기준으로 판단했는지 확인할 수 있어야 하므로, 계산 결과와 UI 피드백을 함께 연결했습니다.

확인 가능한 파일 또는 화면: ViewController.swift, bmi-result.png

3) WKWebView 기반 운동 정보 탐색

처리 방식: WebViewController에서 WKWebView를 사용해 앱 내부에서 운동 관련 검색 또는 정보 페이지를 확인하도록 했습니다.

구현 이유: BMI 결과 이후 사용자가 추가 정보를 바로 탐색할 수 있도록 계산 화면과 정보 화면을 탭으로 분리했습니다.

확인 가능한 파일 또는 화면: WebViewController.swift, workout-webview.png

4) AVKit 로컬 운동 영상 재생

처리 방식: VideoViewController에서 AVPlayerViewController를 사용해 bench.mp4, squat.mp4, deadlift.mp4 같은 로컬 영상을 선택해 재생합니다.

구현 이유: 네트워크 상태와 관계없이 과제 시연 환경에서 운동 영상 재생 흐름을 확인하기 위해 로컬 리소스를 연결했습니다.

확인 가능한 파일 또는 화면: VideoViewController.swift, bench.mp4, squat.mp4, deadlift.mp4, workout-video.png

5) 운동 계획 입력값 처리

처리 방식: PlanViewController에서 UISlider, UIStepper, UISegmentedControl 값을 읽어 운동 강도, 시간, 세트 수에 따른 요약 문구를 갱신했습니다.

구현 이유: 계산과 정보 확인 이후 사용자가 자신의 운동 계획을 간단히 설정하는 흐름까지 이어지도록 하기 위해서입니다.

확인 가능한 파일 또는 화면: PlanViewController.swift, workout-plan.png

6) Storyboard 기반 탭 화면 분리

처리 방식: Main.storyboard에서 Tab Bar Controller를 사용해 BMI, 운동정보, 운동영상, 운동계획 화면을 탭으로 나누었습니다.

구현 이유: 화면 전환 로직을 복잡하게 만들기보다 각 기능을 독립 탭으로 분리해 사용자가 원하는 흐름을 바로 선택하도록 했습니다.

확인 가능한 파일 또는 화면: Main.storyboard, docs/screenshots

7) 앱 리소스와 시작 화면

처리 방식: Assets.xcassets에 앱 아이콘과 이미지 리소스를 두고, LaunchScreen.storyboard로 앱 시작 화면을 구성했습니다.

구현 이유: 앱 실행 전후의 화면 흐름과 리소스 위치를 확인할 수 있어야 전체 iOS 프로젝트 구성이 명확해집니다.

확인 가능한 파일 또는 화면: Assets.xcassets, LaunchScreen.storyboard, app-icon.png, launch-screen.png

구현 흐름 상세

1) 키/체중 입력

사용자가 BMI 계산 화면에서 키와 체중을 입력합니다.

2) 입력값 검증

빈 값과 숫자 변환 실패를 확인해 잘못된 입력이 계산으로 넘어가지 않도록 막습니다.

3) BMI 계산

검증된 키와 체중을 BMI 공식에 적용해 결과값을 계산합니다.

4) 성별 기준 정상 범위 분기

성별 선택값을 기준으로 정상 BMI 범위를 나누고 결과 판정 기준을 적용합니다.

5) 결과 UI 피드백

결과 문구, 색상, 이미지 테두리를 바꿔 계산 결과를 시각적으로 확인하게 합니다.

6) 운동 정보 WebView 확인

운동 정보 탭에서 WKWebView로 외부 운동 관련 정보를 앱 내부에서 확인합니다.

7) 운동 영상 재생

운동 영상 탭에서 로컬 mp4 파일을 선택하고 AVPlayerViewController로 재생합니다.

8) 운동 계획 설정

운동 계획 탭에서 강도, 시간, 세트 수를 조정하고 요약 문구를 갱신합니다.

개선 여지

BMI 기준은 학습용 예시 기준이며 의료 판단을 대체하지 않습니다. 현재 기록 저장 기능이 없으므로 사용자별 기록과 목표 저장을 추가할 수 있습니다.

구현 중 확인한 한계와 개선 방향

1) BMI 기록 저장

현재 앱은 계산 결과를 화면에 표시하지만 기록을 저장하지 않습니다. 이후 UserDefaults, 파일 저장, Core Data 등을 검토해 BMI 변화 기록을 남길 수 있습니다.

2) 사용자별 목표 저장

운동 계획은 화면 입력값에 따라 요약 문구를 갱신하는 구조입니다. 사용자별 목표와 계획을 저장하면 앱 재실행 후에도 계획을 이어갈 수 있습니다.

3) 운동 정보 로컬 데이터화

WebView는 외부 페이지 의존성이 있습니다. 주요 운동 정보를 로컬 데이터로 분리하면 네트워크 상태와 관계없이 기본 정보를 제공할 수 있습니다.

4) HealthKit 연동 검토

건강관리 앱으로 확장하려면 HealthKit 연동 가능성을 검토할 수 있습니다. 단, 사용자 권한 요청과 개인정보 처리 기준을 함께 설계해야 합니다.

5) 영상 리소스 출처와 권한 명확화

영상 자료는 학습 및 과제 시연용 리소스입니다. 실제 공개 서비스 배포를 전제로 한다면 출처와 사용 권한이 명확한 자료로 교체해야 합니다.
