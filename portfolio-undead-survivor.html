프로젝트 개요

Unity와 C#으로 제작한 Android 기반 모바일 생존형 액션 게임입니다. 사용자는 캐릭터를 선택한 뒤 직접 이동하고, 주변 적 탐지 기반 자동 공격, 시간별 적 스폰, 경험치 획득, 레벨업 보상, 생존 또는 사망 결과 화면을 차례로 경험합니다. 구현 범위는 포트폴리오용 저장소에 정리된 주요 C# 스크립트, APK, 스크린샷, 게임 흐름 문서 기준으로 게임 루프와 UI 흐름을 설명하는 데 맞췄습니다.

Unity C# Android Object Pooling

개발 목적

Undead Survivor는 Unity 원본 프로젝트 전체가 아니라 포트폴리오 확인을 위해 주요 C# 스크립트, 스크린샷, APK, 문서를 정리한 저장소를 기준으로 설명합니다. 상세 페이지에서는 단순히 화면 이미지를 나열하는 대신 GameManager, Player, Scanner, Weapon, Spawner, PoolManager가 어떤 순서로 동작하는지 드러내는 데 초점을 두었습니다.

모바일 환경에서는 조작 부담이 크기 때문에 이동은 사용자가 직접 입력하고, 공격은 주변 적 탐지 기반 자동 공격으로 나누었습니다. 플레이어가 생존 위치를 판단하는 데 집중하도록 하면서도 Scanner와 Weapon을 통해 공격 대상 선택과 피해 처리를 코드에서 검증할 수 있게 했습니다.

생존형 게임에서는 적과 투사체가 반복적으로 생성됩니다. 매번 Instantiate와 Destroy에 의존하면 모바일 환경에서 비용이 커질 수 있으므로 PoolManager가 비활성 오브젝트를 재사용하고, 필요한 경우에만 새로 생성하도록 처리했습니다.

게임 루프는 캐릭터 선택, 게임 시작, 진행 시간 누적, 적 스폰, 경험치 획득, 레벨업 보상, 체력 소진 또는 maxGameTime 도달에 따른 결과 처리로 이어집니다. 각 단계는 화면 전환뿐 아니라 상태값과 UI 갱신이 함께 움직이도록 설계했습니다.

핵심 구현 포인트

1) GameManager 중심의 게임 루프

처리 방식: 게임 시작, 진행 시간, 체력, 경험치, 레벨, 처치 수, 승리/패배 상태를 GameManager에서 관리했습니다. maxGameTime에 도달하면 생존 성공으로, 체력이 소진되면 패배로 분기합니다.

구현 이유: 생존형 게임은 시간과 상태 변화가 결과 화면까지 이어져야 하므로 핵심 상태를 한 지점에서 추적할 필요가 있었습니다.

확인 가능한 파일 또는 화면: GameManager.cs, Result.cs, 생존 결과 화면, 사망 결과 화면

2) Player 이동과 피격 처리

처리 방식: Player.cs에서 입력 기반 이동, 방향 전환, 피격, 사망 처리를 담당하도록 나누었습니다.

구현 이유: 플레이어 조작은 가장 자주 실행되는 로직이므로 상태 관리 코드와 분리해 이동과 생존 상태를 읽기 쉽게 만들었습니다.

확인 가능한 파일 또는 화면: Player.cs, Character.cs, 전투 화면

3) Scanner, Weapon, Bullet 자동 공격

처리 방식: Scanner가 주변 적을 탐지하고 가장 가까운 적을 선택하면, Weapon이 근접 회전 공격 또는 원거리 발사를 수행하고 Bullet이 피해량과 관통 횟수를 처리합니다.

구현 이유: 이동과 공격을 모두 직접 조작하게 하면 모바일 화면에서 부담이 커지므로, 사용자는 이동에 집중하고 공격 판단은 탐지 로직으로 넘겼습니다.

확인 가능한 파일 또는 화면: Scanner.cs, Weapon.cs, Bullet.cs, 전투 화면

4) 진행 시간 기반 적 스폰

처리 방식: Spawner가 진행 시간에 맞는 Spawner.cs 내부 SpawnData 클래스를 선택해 적 생성 흐름을 조정합니다.

구현 이유: 시간이 지날수록 등장 적이나 생성 빈도를 바꿀 수 있어야 생존 루프의 난이도 곡선을 제어할 수 있습니다.

확인 가능한 파일 또는 화면: Spawner.cs, Spawner.cs 내부 SpawnData 클래스, Enemy.cs, 게임 플레이 화면

5) PoolManager 오브젝트 재사용

처리 방식: 적과 투사체를 풀에서 가져오고, 비활성 오브젝트가 있으면 재활성화하며, 없을 때만 Instantiate를 수행합니다.

구현 이유: 모바일 환경에서 반복 생성과 삭제 비용을 줄이고, 전투 중 프레임 저하 가능성을 낮추기 위해 재사용 구조를 적용했습니다.

확인 가능한 파일 또는 화면: PoolManager.cs, Enemy.cs, Bullet.cs

6) 레벨업 보상과 결과 표시

처리 방식: 경험치 조건을 충족하면 LevelUp 화면을 표시하고 보상 후보를 최대 3개까지 보여줍니다. HUD는 체력, 경험치, 레벨, 처치 수, 시간을 갱신하고 Result는 종료 상태를 표시합니다.

구현 이유: 반복 전투 사이에 성장 선택을 넣고, 플레이 중 상태 변화와 종료 결과가 같은 데이터 흐름에서 이어지도록 하기 위해서입니다.

확인 가능한 파일 또는 화면: LevelUp.cs, ItemData.cs, Item.cs, Gear.cs, HUD.cs, Result.cs

구현 흐름 상세

1) 캐릭터 선택

캐릭터 선택 화면에서 해금 상태와 선택 가능 여부를 점검한 뒤 게임을 시작합니다.

2) 게임 시작

GameManager가 진행 시간, 체력, 경험치, 레벨, 처치 수를 초기화하고 플레이 상태를 활성화합니다.

3) 이동과 자동 공격

Player는 입력값으로 이동하고, Scanner와 Weapon은 가까운 적 탐지와 공격 실행을 담당합니다.

4) 적 스폰과 풀 사용

Spawner가 진행 시간에 맞는 Spawner.cs 내부 SpawnData 클래스를 선택하고, PoolManager에서 적 오브젝트를 가져옵니다.

5) 경험치와 레벨업

적 처치 후 경험치를 누적하고 조건을 충족하면 LevelUp UI에서 Item 또는 Gear 효과를 선택합니다.

6) 결과 처리

maxGameTime 도달 또는 체력 소진 조건에 따라 Result 화면을 표시하고, AchievementManager가 해금 조건을 평가합니다.

파일별 역할

GameManager.cs

게임 상태, 시간, 체력, 경험치, 처치 수, 결과 분기를 관리합니다.

Player.cs · Character.cs

플레이어 이동, 방향 전환, 피격, 사망 처리를 담당합니다.

Scanner.cs · Weapon.cs · Bullet.cs

주변 적 탐지, 근접/원거리 공격, 투사체 피해와 관통 처리를 맡습니다.

Spawner.cs

진행 시간 기반 스폰과 Spawner.cs 내부 SpawnData 클래스 선택을 처리합니다.

PoolManager.cs · Enemy.cs

적 오브젝트 재사용과 적 상태 처리를 담당합니다.

LevelUp.cs · ItemData.cs · Item.cs · Gear.cs

레벨업 후보 표시와 선택 보상 적용을 처리합니다.

HUD.cs · Result.cs

플레이 정보 갱신과 생존/사망 결과 화면 표시를 맡습니다.

AchievementManager.cs · AudioManager.cs

캐릭터 해금 조건과 게임 오디오 호출을 관리합니다.

구현 중 확인한 한계와 개선 방향

1) GameManager 책임 분리

현재 GameManager가 시간, 체력, 경험치, 결과 처리를 함께 맡습니다. 이후 상태 관리, UI 전환, 오디오 호출을 나누면 변경 영향을 줄일 수 있습니다.

2) 피격 쿨타임과 무적 시간

피격 판정이 자주 발생하는 상황을 더 안정적으로 제어하려면 피격 쿨타임과 짧은 무적 시간을 추가해 체력 감소를 조절할 필요가 있습니다.

3) 적 종류별 공격력 분리

적 종류별 공격력과 행동 패턴을 세분화하면 난이도 조절 근거를 코드에서 더 명확히 볼 수 있습니다.

4) 보스전과 스테이지 패턴

maxGameTime까지 버티는 목표 외에 보스전이나 시간대별 패턴을 추가하면 생존 목표를 더 다양하게 검증할 수 있습니다.

5) 풀 초기 개수와 최대 개수 설정

초기 생성 개수와 최대 생성 개수를 명시하면 메모리 사용량과 순간 생성 비용을 더 예측 가능하게 관리할 수 있습니다.
