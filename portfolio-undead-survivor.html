프로젝트 개요

Unity와 C#으로 제작한 Android 기반 모바일 생존형 액션 게임입니다. 사용자는 캐릭터를 선택한 뒤 직접 이동하고, 주변 적 탐지 기반 자동 공격, 시간별 적 스폰, 경험치 획득, 레벨업 보상, 생존 또는 사망 결과 화면까지 이어지는 플레이 루프를 경험합니다. 이 상세 페이지는 Unity 원본 프로젝트 전체가 아니라, 포트폴리오 검토를 위해 정리한 주요 C# 스크립트, APK, 스크린샷, 문서를 기준으로 구현 흐름을 설명합니다.

Unity C# Android Object Pooling

개발 목적

모바일 환경에서 이동과 공격을 모두 직접 조작하면 화면 입력 부담이 커집니다. 이 프로젝트는 이동은 사용자가 직접 입력하고, 공격은 Scanner가 주변 적을 찾는 자동 탐지 방식으로 분리해 생존 위치 판단에 집중하도록 만들었습니다.

생존형 게임은 시간, 체력, 경험치, 레벨, 결과 화면이 끊기지 않고 이어져야 합니다. GameManager를 기준으로 주요 상태를 추적하고, 생존 성공과 사망 조건에 따라 Result 화면으로 전환되도록 연결했습니다.

적과 투사체는 전투 중 반복해서 등장하므로 PoolManager가 비활성 오브젝트를 재사용하게 했습니다. 이를 통해 매번 생성하고 제거하는 구조를 제한하고, 모바일 실행 환경에서 발생할 수 있는 런타임 비용을 줄이는 방향으로 설계했습니다.

레벨업 보상, HUD, 결과 화면은 플레이 중 상태 변화가 화면에 드러나도록 연결했습니다. 포트폴리오 페이지에서는 주요 C# 스크립트, 문서, Android APK를 기준으로 구현 범위를 검토할 수 있게 정리했습니다.

핵심 구현 포인트

1) GameManager 중심의 게임 상태 관리

처리 방식: 게임 시작, 진행 시간, 체력, 경험치, 레벨, 처치 수, 생존 성공, 사망 결과를 GameManager에서 추적합니다. maxGameTime 도달과 체력 소진 조건에 따라 Result 화면으로 전환합니다.

구현 이유: 생존형 게임은 시간과 상태 변화가 결과 화면까지 이어져야 하므로 핵심 상태를 한 지점에서 파악할 수 있게 했습니다.

확인 가능한 파일 또는 화면: GameManager.cs, Result.cs, 생존 결과 화면, 사망 결과 화면

2) Player/Character 기반 이동과 능력치 보정

처리 방식: Player.cs는 입력 기반 이동, 방향 전환, 피격, 사망을 담당하고 Character.cs는 선택 캐릭터의 이동 속도, 공격 속도, 피해량, 투사체 수 보정값을 제공합니다. Hand.cs는 캐릭터 방향에 맞춰 손 위치와 정렬을 보정합니다.

구현 이유: 조작 로직과 캐릭터별 수치를 분리하면 캐릭터 변경이 이동 코드에 직접 영향을 주지 않습니다.

확인 가능한 파일 또는 화면: Player.cs, Character.cs, Hand.cs, 캐릭터 선택 화면, 전투 화면

3) Scanner, Weapon, Bullet 자동 공격 구조

처리 방식: Scanner가 주변 적 중 가장 가까운 대상을 갱신하면 Weapon이 무기 타입에 따라 근접 회전 공격 또는 원거리 발사를 실행합니다. Bullet은 피해량, 관통 횟수, 충돌 후 비활성화를 담당합니다.

구현 이유: 이동과 공격을 모두 직접 조작하면 모바일 화면에서 부담이 커지므로, 사용자는 이동에 집중하고 공격 판단은 탐지 로직으로 넘겼습니다.

확인 가능한 파일 또는 화면: Scanner.cs, Weapon.cs, Bullet.cs, 전투 화면

4) Spawner와 SpawnData 기반 시간별 적 생성

처리 방식: Spawner가 진행 시간에 맞는 Spawner.cs 내부 SpawnData 클래스를 선택하고, 스폰 주기, 적 종류, 체력, 이동 속도에 맞춰 적을 배치합니다.

구현 이유: 시간이 지날수록 등장 적과 생성 빈도를 바꿀 수 있어야 난이도 곡선을 조정할 수 있습니다.

확인 가능한 파일 또는 화면: Spawner.cs, SpawnData, Enemy.cs, 전투 화면

5) PoolManager 오브젝트 재사용

처리 방식: 적과 투사체를 풀에서 가져오고, 비활성 오브젝트가 있으면 다시 활성화하며, 없을 때만 Instantiate를 수행합니다.

구현 이유: 모바일 환경에서 반복 생성과 삭제 비용을 줄이고 전투 중 프레임 저하 가능성을 낮추기 위해 재사용 구조를 적용했습니다.

확인 가능한 파일 또는 화면: PoolManager.cs, Enemy.cs, Bullet.cs

6) Enemy 피격·넉백·사망·경험치 지급

처리 방식: Enemy.cs는 투사체 충돌 시 피해를 반영하고, 체력이 남아 있으면 피격 애니메이션과 넉백을 실행합니다. 체력이 0 이하가 되면 사망 상태로 전환하고 처치 수와 경험치를 지급합니다.

구현 이유: 전투 결과가 성장과 결과 화면에 반영되어야 하므로 적 상태 변화와 보상 지급을 명확히 연결했습니다.

확인 가능한 파일 또는 화면: Enemy.cs, GameManager.cs, HUD.cs, 전투 화면

7) LevelUp, ItemData, Item, Gear 보상 선택

처리 방식: 경험치가 기준치에 도달하면 LevelUp이 보상 후보를 최대 3개 표시하고, ItemData와 Item이 선택 정보를 연결합니다. Gear는 장비 효과를 공격 주기와 이동 속도에 반영합니다.

구현 이유: 반복 전투 사이에 성장 선택을 넣어 플레이 중 의사결정이 상태 변화로 이어지도록 했습니다.

확인 가능한 파일 또는 화면: LevelUp.cs, ItemData.cs, Item.cs, Gear.cs, 레벨업 보상 화면

8) HUD, Result, AchievementManager, AudioManager 결과·UI·사운드 연결

처리 방식: HUD가 경험치, 레벨, 처치 수, 시간, 체력을 갱신하고 Result가 생존 또는 사망 결과를 표시합니다. AchievementManager는 캐릭터 해금 조건과 안내 문구를 평가하고, AudioManager는 배경음과 효과음 채널을 다룹니다.

구현 이유: 플레이 상태, 보상, 결과, 사운드가 따로 움직이지 않도록 게임 상태 변화에 맞춰 화면과 오디오를 연결했습니다.

확인 가능한 파일 또는 화면: HUD.cs, Result.cs, AchievementManager.cs, AudioManager.cs, 생존 결과 화면, 사망 결과 화면

구현 흐름 상세

1) 캐릭터 선택

게임 시작 전 사용할 캐릭터를 선택합니다. 캐릭터별 능력치와 해금 상태를 기준으로 선택 가능 여부를 판단합니다.

2) 게임 시작

GameManager가 플레이어를 활성화하고 진행 시간과 게임 상태를 초기화합니다. 시작 아이템, HUD, 스폰, 사운드도 플레이 상태로 전환됩니다.

3) 플레이어 이동

Player가 입력 축을 읽어 이동 방향을 계산하고 Rigidbody2D.MovePosition으로 위치를 갱신합니다. Character와 Hand는 능력치와 방향 보정을 제공합니다.

4) 적 스폰

Spawner가 진행 시간에 맞는 SpawnData를 선택합니다. 생성된 적은 PoolManager를 통해 재사용됩니다.

5) 주변 적 탐지

Scanner가 주변 적 중 가장 가까운 대상을 갱신합니다. 이 대상 정보가 Weapon의 공격 실행 기준이 됩니다.

6) 자동 공격

Weapon이 무기 타입에 맞춰 근접 회전 공격 또는 원거리 발사를 실행합니다. Bullet은 피해량과 관통 횟수를 반영한 뒤 필요하면 비활성화됩니다.

7) 경험치 획득

Enemy는 피해, 넉백, 사망 상태를 반영합니다. 처치 시 GameManager에 처치 수와 경험치가 누적됩니다.

8) 레벨업 보상 선택

경험치가 기준치에 도달하면 LevelUp이 보상 후보를 표시합니다. 선택한 Item 또는 Gear 효과가 무기와 장비 성장에 반영됩니다.

9) 생존 성공 또는 사망 결과

제한 시간 동안 생존하면 생존 성공으로, 체력이 0 이하가 되면 사망으로 전환됩니다. Result와 AudioManager가 결과 화면과 사운드를 연결합니다.

구현 중 확인한 한계와 개선 방향

1) GameManager 책임 분리

현재 GameManager가 시작, 진행, 정지, 체력, 경험치, 결과 화면, 사운드 호출까지 넓게 맡고 있습니다. 규모가 커지면 GameStateManager, PlayerStats, ResultController, SoundController로 나눠 변경 범위를 줄일 수 있습니다.

2) PoolManager 설정과 디버깅 정보

현재 풀은 프리팹 배열의 인덱스를 기준으로 동작합니다. 초기 생성 개수, 최대 생성 개수, enum 또는 이름 기반 조회, 풀 상태 디버깅 정보를 추가하면 런타임 생성 비용과 메모리 사용량을 더 예측하기 쉽습니다.

3) 자동 공격 타겟팅 기준

현재 자동 공격은 가까운 적을 기준으로 대상을 선택합니다. 보스, 일반 적, 체력이 낮은 적처럼 우선순위를 세분화하면 상황별 공격 판단을 보완할 수 있습니다.

4) 스폰 데이터와 난이도 조정

시간 기반 SpawnData만으로도 기본 난이도 조정은 가능하지만, 웨이브 단위 스폰, 보스 등장 시간, 맵 위치별 스폰 확률, 난이도별 스폰 데이터 분리를 추가하면 생존 목표를 더 다양하게 검토할 수 있습니다.

5) 결과/UI 기록과 화면 비율 대응

HUD와 Result는 현재 플레이 상태와 생존/사망 결과를 보여줍니다. 이후 결과 화면 통계, 최고 기록 저장, 캐릭터별 기록 분리, 모바일 화면 비율별 UI 보정을 추가해 검토 지점을 늘릴 수 있습니다.
